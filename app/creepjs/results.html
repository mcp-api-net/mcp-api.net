How the distances are computed

Each component (navigator, canvas, WebGL, audio…) is flattened into leaf values. Every leaf gets a distance from 0 (identical) to 1 (completely different):

  • lists of values (fonts, voices, extensions, window keys…): Jaccard distance, 1 − |A∩B| / |A∪B|. Elements only in B are shown in green, elements only in A are struck through in red.
  • numbers: relative difference |a−b| / max(|a|,|b|), capped at 1. Audio sums and measured sizes that drift slightly give small distances, not a full mismatch.
  • strings, booleans, data URIs: 0 if equal, else 1.
  • missing on one side: 1.

Component distance is the mean of its leaf distances. Weighted distance averages component distances using the weights shown on each row, which reflect how much identifying entropy a component carries (canvas, WebGL, audio and fonts count most; error bookkeeping counts least). Unweighted treats every component equally. Components changed counts components whose CreepJS $hash differs. Fuzzy bins compares CreepJS's 64-character fuzzy hash: each hex character is a hash of one bin of metrics, so the number of differing characters estimates how much of the fingerprint moved. FP ID is the hash of the stable subset (the components marked in FP ID).
